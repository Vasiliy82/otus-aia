# AI-ассистент кредитного аналитика — Project Charter

## О проекте

Банк инициирует проект по внедрению AI-ассистента для поддержки кредитных и комплаенс-аналитиков при оценке контрагентов. Система должна объединить нормативную базу, внутренние методики и финансовую отчётность в единый интерактивный контур с разграничением доступа и полным соответствием требованиям регулятора.

## Бизнес-ценность

| Проблема сегодня | Решение |
|-----------------|---------|
| Аналитик вручную ищет по 3–5 источникам при оценке одного контрагента | Единый ассистент агрегирует нормативку, отчётность и внутренние политики |
| Риск пропустить применимую норму или внутреннее ограничение | GraphRAG связывает норму → политику → контрагента → рисковый фактор |
| Нет контроля: кто какую методику видит | RBAC на уровне фрагментов документа — регуляторное требование |
| Облачные AI-сервисы несовместимы с ФЗ-152 и требованиями ЦБ РФ | On-prem инференс, данные не покидают контур |

## Почему сначала PoC, а не сразу продакшн

Банк находится в начале пути формирования AI-компетенций:

- В штате **нет специалистов по ML/AI** — проект первым делом строит внутреннюю экспертизу.
- Отдел эксплуатации работает исключительно с **PostgreSQL**; выделенного MLOps-инженера нет (вакансия открыта, найм запланирован на Q3 2026).
- **GPU-мощности** в бюджет следующего года ещё не включены — закупочная процедура требует обоснования ROI.
- Регуляторный контур требует аудита и согласования до полного запуска.

PoC — это **управляемый эксперимент** на ограниченном датасете, который даёт совету директоров ответ: «работает ли архитектура» до принятия инвестиционного решения о масштабировании.

## Критерий выхода из PoC

Технический комитет принимает решение GO/NO-GO на основании:

1. Демонстрация GraphRAG: ответ с трассировкой через граф знаний.
2. Демонстрация RBAC: пользователь без прав не получает закрытый фрагмент.
3. Архитектура on-prem подтверждена без внешних AI API.
4. Представлена архитектура MVP с дорожной картой замены мок-компонентов.
