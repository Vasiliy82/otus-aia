# ADR-009: Ранжирование контекста — RRF + Cross-Encoder

## Status

Accepted

## Context

GraphRAG (ADR-002) даёт два независимых источника кандидатов на чанк: dense-поиск в Qdrant (косинусное сходство) и graph expansion в Neo4j. Их нужно слить в единый отранжированный контекст перед подачей в генератор.

Наивное слияние через взвешенную сумму скоров математически некорректно:

- Косинусное сходство — **непрерывная** величина в своей шкале; graph-скор часто задаётся **дискретными** константами (например, 1.0 или 0.8 по типу узла/ребра).
- Жёсткое сложение разных шкал позволяет статическому графовому бусту перекрыть семантическую релевантность. Пример: нерелевантный чанк с косинусом `0.3`, получив graph-буст, выходит на итоговый скор `~0.8` и **вытесняет** семантически точный чанк с косинусом `0.75`.

На PoC применялась осознанно упрощённая эвристика `final_score = vector_score + 0.5 · graph_score` (`backend/rerank/score.py`, см. ADR-007) — её достаточно для проверки гипотезы, но не для production-качества контекста.

## Alternatives

### 1. Взвешенная сумма скоров (PoC-эвристика)

- Плюсы: тривиальна, детерминирована, без моделей
- Минусы: смешивает несопоставимые шкалы; статический буст перекрывает релевантность; веса подбираются вручную и нестабильны

### 2. Только RRF (Reciprocal Rank Fusion)

- Плюсы: работает с **позициями**, а не абсолютными скорами — полностью нивелирует разницу шкал; не требует обучения; устойчив
- Минусы: не учитывает глубокую семантику пары запрос–чанк; качество ограничено качеством исходных списков

### 3. RRF + Cross-Encoder rerank (выбрано)

- Плюсы: RRF корректно сливает dense- и graph-списки по рангам; cross-encoder оценивает релевантность пары `(query, chunk)` на основе глубокого внимания — максимальная точность финального порядка контекста
- Минусы: дополнительная модель (cross-encoder) и инференс; требует GPU-сервиса

## Decision

Заменить эвристику на двухступенчатое ранжирование:

1. **RRF (Reciprocal Rank Fusion).** Для dense- и graph-списков считаем `score = Σ 1/(k + rank_i)` (k ≈ 60). Слияние идёт по относительным позициям чанков, что устраняет проблему несопоставимых шкал.
2. **Cross-Encoder rerank.** Top-N кандидатов после RRF переранжируются локальной cross-encoder моделью `score(query, chunk)`. Инференс cross-encoder изолирован в Triton по gRPC (ADR-008).

Узел `rerank` LangGraph-графа реализует именно эту связку (ADR-005). PoC-эвристика остаётся только как зафиксированное упрощение этапа PoC (ADR-007).

## Consequences

**Плюсы:** корректная математика слияния; семантически релевантный контекст не вытесняется статическим графовым бустом; точность ранжирования максимальна перед генерацией; качество измеряется регрессионными прогонами (RAGAS/DeepEval, подсистема AI Quality & MLOps).

**Минусы:** дополнительная модель и инференс-нагрузка; рост latency на шаг rerank (снижается батчингом в Triton и ограничением top-N).

**Риски:** неверный выбор `k` в RRF или слабый cross-encoder — снижается экспериментами на golden set и сравнением baseline/new version перед релизом (release gate).

**Дополнительно:** в `architecture/mvp` добавлен компонент `RRF Fusion`, `Reranker` использует `Rerank Client` → Triton; sequence-диаграмма `POST /ask` отражает шаги RRF и cross-encoder.

## Compliance & Security

Ранжирование выполняется **после** RBAC-фильтрации (ADR-006): cross-encoder и RRF не могут вернуть в контекст недоступный роли чанк. Cross-encoder — локальная модель в закрытом контуре (Triton), данные не покидают периметр.
