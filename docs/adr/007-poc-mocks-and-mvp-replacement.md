# ADR-007: Мок-компоненты в PoC и план замены на MVP

## Status

Accepted

## Context

Ряд компонентов целевой архитектуры не может быть введён в строй на этапе PoC по объективным операционным причинам:

- **GPU-оборудование не закуплено.** Производительный локальный LLM требует серверных GPU (минимум 24 ГБ VRAM). Закупочная процедура занимает 3–4 месяца и инициируется только после GO-решения Технического комитета по итогам PoC.
- **MLOps-инженера в штате нет.** Вакансия открыта; до прихода специалиста развёртывание и эксплуатация специализированных AI-сервисов (reranker, embedding service в production-режиме, Qdrant cluster) нецелесообразны.
- **Neo4j не в зоне компетенций DBA.** Переход к production graph store требует обучения команды и разработки операционных процедур — после найма MLOps и GO-решения.
- **ИБ-аудит незавершён.** Vault, полноценный OTel-стек и реальный юридический корпус могут быть введены только после согласования с Службой информационной безопасности.

Наличие мок-компонентов — не упрощение ради скорости, а **честная фиксация операционных ограничений** с явным планом устранения. Ключевые компоненты, проверяющие бизнес-гипотезу (RBAC, GraphRAG-пайплайн, LangGraph, guardrails), реализованы без упрощений.

## Alternatives

### 1. Реализовать всё production-компоненты немедленно

- Плюсы: нет технического долга
- Минусы: **невозможно** — GPU не закуплен, MLOps-инженера нет; риск затянуть GO/NO-GO решение на 6–9 месяцев

### 2. Честные мок-компоненты + архитектура MVP с планом замены (выбрано)

- Плюсы: PoC даёт Техническому комитету ответ в разумные сроки; технический долг прозрачен; критические компоненты не мокируются
- Минусы: качество формулировок LLM на PoC ограничено шаблоном

### 3. Только документация без реализующего кода

- Плюсы: меньше работы
- Минусы: не подтверждает работоспособность архитектуры; нет основания для GO-решения

## Decision

Зафиксировать реестр мок-компонентов с плановыми датами замены:

| Компонент | PoC (сейчас) | MVP / Production | Условие замены |
|-----------|-------------|-----------------|----------------|
| LLM | `MockLLMClient` (шаблонный ответ) | self-hosted Qwen AWQ через vLLM (изолированный inference, gRPC) | После закупки GPU |
| Inference embeddings/reranker | in-process sentence-transformers (CPU) | выделенный Triton Inference Server (GPU, gRPC) — ADR-008 | После закупки GPU + найма MLOps |
| Ранжирование | детерминированная формула `vector + 0.5·graph` | RRF (Reciprocal Rank Fusion) + cross-encoder rerank — ADR-009 | После найма MLOps-инженера (Q3 2026) |
| Graph store | PostgreSQL (таблицы) | Neo4j cluster | После найма MLOps + ИБ-аудит |
| Векторная БД | pgvector (PostgreSQL) | Qdrant cluster | После найма MLOps (Q3 2026) |
| OCR | подготовленные тексты | layout parser + MinIO | Отдельный проект |
| Secrets | `.env` | HashiCorp Vault | После ИБ-аудита |
| Observability | `trace_id` в JSON-логах | OpenTelemetry + Jaeger + Prometheus | После найма MLOps |
| Юридический корпус | синтетические 3 документа | срез реальной нормативки | После согласования с ИБ |
| Streaming | нет | SSE / WebSocket | При разработке UI |

**Компоненты, не подлежащие мокированию на любом этапе:**

- RBAC-фильтрация фрагментов
- LangGraph state machine (оркестратор)
- GraphRAG двухшаговый поиск с graph expansion
- Input/output guardrails

## Consequences

**Плюсы:** прозрачный технический долг; Технический комитет понимает, что именно проверено, а что отложено; дорожная карта замены компонентов для MVP.

**Минусы:** демонстрация ограничена шаблонными ответами LLM на PoC.

**Риски:** неверная интерпретация мок-компонентов как признак слабости архитектуры — снижается чёткими ADR и диаграммами MVP, где показана целевая система.

## Compliance & Security

Мок-компоненты **не отключают** RBAC и guardrails. Аудиторский след (`trace_id`) сохраняется даже на PoC. Синтетические данные не содержат персональных данных, соответствие ФЗ-152 проверяется до перехода к реальному корпусу.
