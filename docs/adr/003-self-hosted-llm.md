# ADR-003: Self-hosted LLM вместо облачных API

## Status

Accepted

## Context

Требование Службы информационной безопасности банка и нормативные требования ЦБ РФ / ФЗ-152 исключают передачу данных контрагентов и внутренних документов банка во внешние API. Использование OpenAI, Anthropic, YandexGPT и аналогичных облачных сервисов недопустимо — это не архитекторский выбор, а регуляторное ограничение.

Дополнительно: GPU-оборудование для production-инференса ещё не закуплено (закупочная процедура инициируется после GO-решения по PoC). Это означает, что на этапе PoC необходимо предусмотреть механизм работы без GPU при сохранении production-совместимого интерфейса.

## Alternatives

### 1. Публичные облачные API (OpenAI, Anthropic и др.)

- Плюсы: наилучшее качество ответов, минимальный time-to-market
- Минусы: **нарушение требований ИБ и регулятора**; данные уходят за пределы контура банка; неприемлемо

### 2. Self-hosted OSS (Qwen, DeepSeek, Saiga) + vLLM / SGLang

- Плюсы: данные остаются в контуре; соответствие ФЗ-152; гибкость настройки под корпоративный домен
- Минусы: требует GPU (VRAM от 24 ГБ), MLOps-компетенции, инфраструктурных процедур

### 3. `MockLLMClient` на PoC + self-hosted на MVP (выбрано)

- Плюсы: PoC проверяет архитектуру без GPU; интерфейс `LLMClient` унифицирован и готов к замене; нет зависимости от сроков закупки оборудования
- Минусы: качество формулировок ответов на PoC ограничено шаблоном mock-клиента

## Decision

**PoC:** единый интерфейс `LLMClient` реализован через `MockLLMClient` — шаблонный ответ по списку переданных фрагментов.

**MVP:** self-hosted **Qwen 2.5 / 3** (или аналог по бенчмаркам) через **vLLM** с квантованием AWQ/GGUF под 24 ГБ VRAM. Выбор конкретной модели фиксируется отдельным ADR при старте MVP.

## Consequences

**Плюсы:** соблюдение требований регулятора и ИБ; единый контракт `LLMClient` для оркестратора; замена mock → production без изменения пайплайна.

**Минусы:** на PoC формулировки LLM — шаблонные; демонстрация акцентируется на архитектуре и проверенных компонентах (RBAC, GraphRAG, LangGraph).

**Риски:** галлюцинации LLM в production — снижается GraphRAG-контекстом, guardrails и обязательными ссылками на источники в каждом ответе.

## Compliance & Security

Запрет вывода без источников реализован в output guardrail. Каждый ответ содержит `trace_id` для аудита. Обучение и файнтюнинг на данных банка — отдельный проект с соответствующим ИБ-согласованием.
