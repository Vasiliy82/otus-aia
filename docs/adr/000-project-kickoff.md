# ADR-000: Kickoff проекта курсовой работы

## Status

Accepted

## Context

Курсовой проект OTUS «AI-Архитектор» требует enterprise-артефакта: on-prem платформа GraphRAG для корпоративных знаний с Security-by-Design. Сроки защиты ограничены; команда — один участник (solo). Нужно зафиксировать цели, обязательства и границы PoC/MVP до реализации кода.

## Alternatives

### 1. Только архитектурная документация без кода

- Плюсы: быстрее, меньше риска срыва сроков из-за инфраструктуры
- Минусы: не закрывает требование «система шевелится»; слабее портфолио

### 2. PoC-код + архитектура MVP (выбранный путь)

- Плюсы: демонстрация GraphRAG, RBAC, LangGraph; соответствует методичке
- Минусы: выше трудозатраты на data prep и инфраструктуру

### 3. Сразу полный production MVP в коде

- Плюсы: максимальная «зрелость» на бумаге
- Минусы: нереалистично за срок курса; размывает фокус архитектора

## Decision

Вести monorepo с **рабочим PoC** (Python, PostgreSQL, подготовка данных через `make`) и **архитектурным MVP** (диаграммы, sizing, ADR без полной реализации кластеров). Документация и код синхронизируются в `docs/` и `backend/`.

## Consequences

**Плюсы:** честная позиция для защиты; поэтапная сдача; ADR ведут историю решений.

**Минусы:** техдолг PoC (моки LLM, упрощённый граф в PostgreSQL).

**Риски:** нехватка GPU на демо — mitigated квантованием и записью видео заранее.

**Дополнительно:** чеклист сдачи в [docs/requirements.md](../requirements.md).

## Compliance & Security

Обязательства: данные и инференс в закрытом контуре; без OpenAI/Anthropic API; RBAC и guardrails — не опциональны.
