# ADR-006: RBAC на уровне фрагментов документа

## Status

Accepted

## Context

Требование ИБ-политики банка и Положения о коммерческой тайне: доступ к внутренним методикам оценки рисков, закрытым аналитическим регламентам и конфиденциальным разделам политик — только для сотрудников с соответствующей ролью. Недостаточно ограничивать доступ на уровне всего документа: один документ может содержать разделы с разным грифом. Фрагмент (chunk) — минимальная единица, для которой имеет смысл управлять доступом.

Пример: итоговая методика оценки риска — документ с открытым введением и закрытым алгоритмическим разделом. Аналитик видит введение, но не видит расчётные формулы; риск-менеджер видит всё.

## Alternatives

### 1. RBAC только на уровне документа

- Плюсы: проще администрировать ACL
- Минусы: слишком груба — либо весь документ доступен, либо нет; не покрывает смешанные грифы внутри одного документа

### 2. RBAC на уровне фрагмента (выбрано)

- Плюсы: гранулярность соответствует требованиям ИБ; поле `allowed_roles text[]` на каждом фрагменте; прямое тестирование: `analyst` не получает `ch_003`
- Минусы: требует поддержки `allowed_roles` при ingestion каждого документа

### 3. ABAC / policy engine (OPA)

- Плюсы: максимальная гибкость enterprise-уровня
- Минусы: избыточная сложность для PoC; требует отдельного OPA-сервиса и ИБ-аудита; целесообразно рассмотреть при масштабировании MVP

## Decision

Хранить поле `allowed_roles text[]` на каждом **фрагменте** в PostgreSQL. При векторном поиске и расширении графа применять фильтр по роли текущего пользователя. Роли в системе: `analyst`, `risk_manager` (расширяемо при переходе к MVP через интеграцию с IdP банка).

## Consequences

**Плюсы:** выполнено требование ИБ-политики; автоматические тесты покрывают кейс «закрытый фрагмент недоступен»; структура ACL прозрачна и аудируема.

**Минусы:** роли дублируются в pgvector payload для pre-filter запроса — синхронизация при ingestion обязательна.

**Риски:** утечка закрытого фрагмента через graph expansion — предотвращается применением RBAC-фильтра **после** расширения графа, а не до.

**Дополнительно:** при переходе к MVP — интеграция с корпоративным IdP (Active Directory / LDAP) для получения ролей пользователя.

## Compliance & Security

Тест соответствия ИБ-требованиям:
- `analyst` + запрос о закрытой методике → `ch_003` отсутствует в контексте ответа;
- `risk_manager` + тот же запрос → `ch_003` присутствует.

Оба теста автоматизированы в pytest и входят в критерии приёмки PoC.
