# PoC: границы и минимальный сценарий

## Бизнес-цель

Проверить, что архитектура GraphRAG-ассистента обеспечивает:

- точный поиск с контекстом «норма → политика → контрагент → риск» при оценке контрагента;
- разграничение доступа к закрытым методикам и внутренним политикам на уровне фрагментов;
- полную работу в закрытом контуре банка без обращения к внешним AI-сервисам.

Результат PoC — основание для решения Технического комитета: **GO** (финансирование MVP) или **NO-GO** (пересмотр подхода).

## Почему PoC, а не сразу MVP

Банк сознательно ограничивает первый этап:

- **Нет внутренней ML-экспертизы.** Проектная команда формируется впервые; PoC — это одновременно прототип системы и обучение команды на боевом стенде.
- **DBA-команда работает только с PostgreSQL.** Введение новых специализированных хранилищ (Neo4j, Qdrant) требует найма или переподготовки, которые запланированы после GO-решения.
- **GPU-оборудование в бюджете MVP.** Закупочная процедура занимает 3–4 месяца; до её завершения производительный локальный LLM недоступен.
- **Регуляторный аудит.** Служба безопасности банка должна проверить архитектуру до того, как в систему попадут реальные данные контрагентов.

## Сценарий

Ассистент кредитного / комплаенс-аналитика отвечает на вопрос по контрагенту с опорой на нормативные и финансовые данные.

Пример запроса:

> Можно ли использовать документы по компании «Ромашка» для предварительного анализа риска? Покажи финансовые признаки и нормативные основания.

Ожидаемый ответ: краткий вывод, нормативные и финансовые фрагменты с ссылками, отказ при отсутствии прав.

## Что реализовано в PoC

| Компонент | Реализация |
|-----------|------------|
| Backend API | FastAPI, 2–3 эндпоинта |
| Оркестратор | LangGraph, граф из 7–8 узлов |
| Поиск | pgvector в PostgreSQL (векторный поиск) |
| Граф знаний | PostgreSQL: таблицы `graph_node` / `graph_edge` |
| Расширение графа | Graph expansion по рёбрам BELONGS_TO, MENTIONS, LINKED_TO |
| Guardrails | regexp + стоп-листы на вход и выход |
| RBAC | Фильтрация фрагментов по полю `allowed_roles` |
| Ingestion | Финансовая отчётность + синтетический юридический срез |
| Тесты | pytest: RBAC, guardrails, graph expansion |

## Ограничения текущего этапа

Следующие компоненты временно заменены заглушками. Дата замены привязана к этапу MVP.

| Компонент | PoC (заглушка) | MVP (целевое решение) | Причина отсрочки |
|-----------|---------------|----------------------|-----------------|
| LLM | `MockLLMClient` (шаблонный ответ) | self-hosted Qwen через vLLM | GPU-оборудование не закуплено |
| Reranker | детерминированная формула score | cross-encoder сервис | нет MLOps-инженера |
| Graph store | PostgreSQL | Neo4j cluster | DBA не владеет Neo4j |
| Векторная БД | pgvector (PostgreSQL) | Qdrant cluster | DBA не владеет Qdrant |
| OCR | подготовленные тексты | layout parser + MinIO | вне цели PoC |
| Secrets | `.env` | HashiCorp Vault | ИБ-аудит до MVP |
| Observability | `trace_id` в JSON-логах | OpenTelemetry + Jaeger | вне цели PoC |
| Юридический корпус | синтетические 3 документа | срез реальной нормативки | очистка данных до MVP |
| Streaming | нет | SSE / WebSocket | вне цели PoC |

## Данные PoC

- **Финансовая отчётность** (открытый датасет): стратифицированная выборка компаний с отчётами 2023–2024.
- **Синтетический юридический срез**: 3 документа, 3 фрагмента, демонстрация RBAC на `ch_003`.
- **Граф знаний**: узлы Document, Chunk, Company, LegalAct, RiskFactor; рёбра BELONGS_TO, MENTIONS, LINKED_TO.

Подготовка: `make data-all` (см. [README.md](../../README.md)).

## Критические тесты

1. Пользователь с ролью `analyst` **не получает** `ch_003` в контексте ответа.
2. Пользователь с ролью `risk_manager` **получает** `ch_003`.
3. Prompt injection блокируется на входе.
4. Ответ без источников блокируется на выходе.
5. Graph expansion добавляет связанный документ/узел к контексту.
